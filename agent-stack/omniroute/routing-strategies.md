# OmniRoute 17ルーティング戦略 解説

OmniRoute はAIリクエストを最適なプロバイダーに自動振り分ける17の戦略を提供します。
教育環境では、コスト・レイテンシ・品質のトレードオフを実際に体験できます。

## 戦略一覧

### 基本戦略（5つ）

| 戦略 | 説明 | ユースケース |
|------|------|-------------|
| **priority** | 優先順位順に試行、最初の成功で確定 | 特定プロバイダーを優先したい場合 |
| **weighted** | 重み付けランダム選択 | 複数プロバイダーに負荷分散したい場合 |
| **round-robin** | 順番にローテーション | 均等にリクエストを分散したい場合 |
| **random** | 完全ランダム | テスト・検証用途 |
| **least-used** | 使用量が最も少ないプロバイダーを選択 | レートリミット回避 |

### コスト最適化戦略（4つ）

| 戦略 | 説明 | ユースケース |
|------|------|-------------|
| **cost-optimized** | 現在のタスクに対して最安プロバイダーを選択 | 予算重視の運用 |
| **headroom** | レートリミットの余裕が最も大きいプロバイダーを選択 | 大量リクエスト処理 |
| **reset-aware** | レートリミットリセット時刻を考慮 | 長時間のバッチ処理 |
| **reset-window** | リセットウィンドウ内の残量を考慮 | 精密なレート管理 |

### 高度な戦略（5つ）

| 戦略 | 説明 | ユースケース |
|------|------|-------------|
| **fill-first** | 一つのプロバイダーの枠を使い切ってから次へ | フリーティアの使い切り |
| **p2c** (Power of Two Choices) | 2つのランダム選択から負荷の低い方を採用 | 分散システムの負荷均衡 |
| **strict-random** | キャッシュ無効化付きランダム | キャッシュ汚染回避 |
| **lkgp** | 過去のパフォーマンス学習 | 継続的な最適化 |
| **auto** | 9因子スコアリングによる自動選択（推奨） | 本番運用のデフォルト |

### コンテキスト連動戦略（3つ）

| 戦略 | 説明 | ユースケース |
|------|------|-------------|
| **context-optimized** | リクエストのコンテキストに基づいてプロバイダー選択 | 日本語タスク→日本語強モデルなど |
| **context-relay** | コンテキストを考慮したリレー転送 | 大規模コンテキストの分割処理 |
| **fusion** | 複数プロバイダーにファンアウト→判定モデルで統合 | 高品質な回答の合成 |

## auto 戦略の9因子スコアリング

`auto` 戦略は以下の9つの因子を総合的にスコアリングして最適なプロバイダーを自動選択します:

1. **Cost** — 現在のトークン単価
2. **Latency** — 直近の応答レイテンシ
3. **Quality** — 過去の応答品質スコア
4. **Availability** — 現在の可用性（ダウン検出）
5. **Rate Limit Headroom** — レートリミットの残量
6. **Context Window** — 要求コンテキスト長との適合性
7. **Model Capability** — タスク要件とのマッチング
8. **Geographic Latency** — ネットワーク遅延
9. **Historical Success Rate** — 過去の成功率

## 学習演習

### 演習1: 戦略比較
同じプロンプトを `cost-optimized`, `priority`, `auto` の3戦略でそれぞれ送信し、
選択されたプロバイダーとレスポンス品質を比較してください。

### 演習2: フォールバック確認
`priority` 戦略でプライマリプロバイダーを無効化し、
セカンダリへの自動フォールバックを確認してください。

### 演習3: RTK圧縮効果測定
長いプロンプト（5000トークン以上）を圧縮有/無で送信し、
トークン消費量の違いをダッシュボードで確認してください。
